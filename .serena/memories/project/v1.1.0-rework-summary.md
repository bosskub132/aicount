# v1.1.0 Auth, Onboarding, Settings & Deletion Rework

## What Changed (2026-03-22/23)

### Auth Foundations
- `/auth/callback` route handles Supabase email verification redirects
- `/signup/verify-email` page shown after registration (with resend button)
- `/api/auth/resend-verification` endpoint (rate-limited, always returns success to prevent enumeration)
- Middleware enforces email verification on both pages AND API routes (403 for unverified API calls)
- `getAppUrl()` utility replaces all hardcoded URLs

### Onboarding (Modal → Dedicated Pages)
- `src/components/onboarding-modal.tsx` DELETED
- 7 route-based pages at `src/app/(onboarding)/onboarding/*`:
  - welcome → workspace → chart-of-accounts → departments → team → template → complete
- `profiles.onboarding_step` (integer 0-6) tracks progress for resume-from-step
- App layout redirects to correct step if `isOnboardingComplete === false`
- Invited users skip onboarding entirely

### Settings Overhaul
- `src/app/(app)/settings/layout.tsx` — sidebar navigation with 4 groups
- Old `settings/tenants/[id]/**` routes DELETED
- New routes: `/settings/profile`, `/settings/security`, `/settings/workspace/*`, `/settings/masterdata/*`, `/settings/accounting/*`
- Workspace-scoped pages read tenantId from `localStorage.getItem("workspaceTenantId")`

### Account & Workspace Deletion
- Soft delete with 30-day grace period
- `profiles`: `deleted_at`, `deletion_scheduled_for` columns
- `tenants`: `deleted_at`, `deletion_scheduled_for`, `deletion_reason` columns
- APIs: `DELETE /api/auth/account`, `POST /api/auth/account/cancel-deletion`, `PATCH /api/tenants/[id]` (soft_delete action), `POST /api/tenants/[id]/cancel-deletion`, `POST /api/tenants/[id]/transfer-ownership`
- Inngest cron jobs: `workspace-purge` (3 AM), `account-purge` (4 AM)
- Workspace deletion requires ownership transfer if other members exist
- Account deletion requires per-workspace choice (transfer or delete)

### Security Hardening
- CSRF (`validateCsrf`) on ALL 14 state-changing API handlers
- Zod validation schemas on ALL 10 mutating API routes
- Upstash Redis rate limiting (`checkRateLimitAsync`) with in-process fallback
- IP detection: `x-real-ip` preferred over `x-forwarded-for`
- Dev auth bypass gated behind `DEV_AUTH_BYPASS=true` env var (no longer auto-grants admin)
- `ensureTenantScope` rejects zero UUID placeholder
- Purge queries require `deletedAt IS NOT NULL`
- HTML escaping in invitation emails
- DB transactions on account delete/cancel operations
- Generic error messages (no Supabase error leakage)
- Middleware catches stale refresh token errors gracefully

## Database Migrations
- `0000_volatile_skaar.sql` — initial schema (already applied in prod)
- `0001_nice_carnage.sql` — soft delete columns + indexes
- `0002_safe_existing_users.sql` — marks existing users as verified + onboarding complete

## New Dependencies
- `@upstash/ratelimit` — distributed rate limiting
- `@upstash/redis` — Redis client for Upstash

## Environment Variables
- `NEXT_PUBLIC_APP_URL` — REQUIRED, must match production domain (CSRF depends on it)
- `UPSTASH_REDIS_REST_URL` — optional, for distributed rate limiting
- `UPSTASH_REDIS_REST_TOKEN` — optional, pair with above
- `DEV_AUTH_BYPASS` — optional, local dev only
